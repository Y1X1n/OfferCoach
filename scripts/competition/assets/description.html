OfferCoach 面试教练

把你的简历和目标岗位交给它，练一场按你经历出题、逐题给证据的模拟面试。
作品形态：支付宝小程序 ｜ 模型：千问 AI 平台 ｜ 创作方向：生活好帮手

1. 作品概况

作品名称
OfferCoach 面试教练
目标用户
正在准备求职面试的学生与职场人
解决的问题
没有真人陪练，练完也不知道差在哪
载体
支付宝小程序（12 个页面）

求职准备里最缺的不是题库，而是「针对你的简历、按目标岗位」的追问和反馈。OfferCoach 让用户粘贴简历与岗位 JD，由千问模型按简历里的项目和 JD 里的必备技能出题；用户逐题作答后， 系统给出五维评分、原文证据、改进建议，最后汇总成一份可复盘的面试报告。

与通用「面试题库」不同，这里的题目和评分都绑定用户自己的经历：问的是他写过的订单重构， 而不是随便一道八股题；评分引用的是他回答里的原句，而不是一句「回答不错」。

2. 使用流程

步骤 用户做什么 系统做什么
① 简历 上传 PDF / Word / 图片，或直接粘贴文本 结构化解析（扫描件走 OCR）、字段修正、默认简历、重解析
② 岗位 粘贴 JD、贴招聘链接，或直接搜索岗位 技能与职责抽取、简历匹配度与缺口、链接抓取失败自动搜索兜底
③ 出题 选择题量、难度与面试官风格，等待 10-30 秒 按缺口与维度配额出题；题库优先，AI 与模板兜底
④ 作答 文字作答，或录音口述；可朗读题目、暂停、跳过、追问 题目逐题解锁；语音走 ASR 转写；提交后即时评分
⑤ 复盘 查看评分与证据，生成报告 五维评分、亮点与风险、改进计划、逐题拆解、分数趋势
⑥ 套餐 额度不足时在套餐页购买 服务端定价、支付宝小程序内调起收银台、回调幂等发放额度
首页：额度与三步引导
简历详情：结构化内容
答题页：评分与原文证据

3. AI 在哪里起作用

3.1 为什么必须有模型

  • 出题：要从非结构化简历里挑出值得追问的项目细节，再对齐 JD 的必备技能，题库无法穷举。
  • 评分：要判断回答是否覆盖了这道题的参考要点，并引用原文作为证据，规则匹配只能做关键词覆盖。
  • 报告：要把多题的低分项归因成可执行的改进计划，而不是罗列分数。
  • 语音与检索：语音作答走 ASR 转写；目标岗位来自链接抓取或联网搜索，再由模型抽取技能。

3.2 降级策略（责任可信）

模型不可用时，系统按既有设计降级为「题库 / 模板题 + 启发式评分」，并在答题页明确标注 「本次评分使用启发式规则」，不会把降级结果伪装成模型结论。额度只在会话创建时扣减， 降级不影响用户已消耗的额度。

演示视频录制于本地环境，未配置模型 Key，因此画面中评分来源为内置规则；线上部署接入千问模型后， 由模型完成出题与评分，界面会显示模型来源，降级时仍会显式标注。

4. 技术方案

支付宝小程序（原生 axml / acss / js）
   │  my.request  →  https://<域名>/api/v1
   ▼
oc-app（Spring Boot 4.2 / JDK 21，模块化单体）
   ├─ oc-identity   注册登录、额度、风控
   ├─ oc-interview  简历、JD、题库、会话状态机、评分、报告
   ├─ oc-ai-client  OpenAI 兼容模型客户端（Base URL / Key 运行时可切换）
   └─ PostgreSQL 16 · Redis 7 · Flyway
   │
   ▼
千问 AI 平台（Chat Completions 兼容接口）

小程序只做展示与交互，不持有任何模型密钥；鉴权、额度、会话状态与降级判断全部在服务端完成， 避免客户端被篡改。小程序首次进入用设备指纹创建体验账号，15 分钟 Token 过期后静默重新登录， 用户无需注册即可完成一次完整练习。支付由 oc-pay 承接：小程序用授权码换买家标识后创建交易， 再调起收银台；金额与套餐始终以服务端为准。

5. 独立功能检测入口

检测入口位于 agent.zip 根目录的 agent.py（Python 3.12，仅标准库）。 它复用作品同一条业务链路：简历结构化 → JD 解析与匹配 → 按缺口出题 → 逐题评分 → 复盘报告， 并把「HTTP 后端」换成本进程内的编排，模型调用仍走 OpenAI 兼容的 Chat Completions。

项说明
运行方式python agent.py --prompt "..."；--version 输出 1.0.0 并以 0 退出
模型配置只读 DASHSCOPE_API_KEY、OPENAI_BASE_URL / DASHSCOPE_BASE_URL，默认 qwen-plus
业务样例samples/resume.md、samples/jd.md、samples/answers.json（按维度分组的示例回答）
输出stdout 打印 Markdown 报告；同时写入 $AGENT_LOG_DIR/report.md、result.json
日志$AGENT_LOG_DIR/agent.log，含每次模型调用的 attempt、状态码与 token 数
退出码0 正常完成；1 模型不可用/执行失败；2 缺少 --prompt
限流处理429 / 5xx 按 Retry-After 指数退避重试，最多 5 次；整体 20 分钟预算
网络仅访问模型服务，不依赖数据库、外部检索或小程序页面

一次完整检测通常产生 8 次模型调用（解析 2 次、匹配 1 次、出题 1 次、评分 3 次、报告 1 次）。

7. 责任与合规

  • 隐私：简历只用于本次结构化与出题，用户可在 Web 端删除；小程序不采集通讯录、位置等无关信息。
  • 边界：评分明确标注「仅用于练习参考，不代表任何企业的真实录用结论」。
  • 不越界：不提供医疗、法律、投资建议；不涉及真实交易、代投简历或对外发送消息。
  • 风控：注册按 IP 与设备双维度限额，额度按套餐与每日上限控制，避免被刷。
  • 可观测：请求、用户、会话三级 Trace 贯通到模型调用，异常可按请求编号回溯。

8. 已知限制

  • 语音作答与题目朗读已接入小程序 API，但录音格式与播放需在支付宝客户端真机验证；预览运行时会提示改用文字。
  • 通知中心接口在后端尚未实现，小程序未放入口，避免空页面。
  • 套餐支付需要 oc-pay 配置与小程序一致的 APPID 与私钥，未配置时套餐页显示「渠道未开通」。
  • 体验版需管理员在支付宝后台添加体验成员；正式发布需完成备案域名与小程序的平台审核。
  • 演示视频录制环境未配置模型 Key，评分来自内置降级规则（见第 3.2 节说明）。
