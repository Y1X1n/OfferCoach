# UI 设计系统与组件库

> 状态：生效 ｜ 版本：v1.4 ｜ 更新：2026-11-11
> 组件基座：**shadcn-vue 风格（Reka UI + Tailwind CSS）**，源码归项目所有；当前采用中性墨灰 + 单一 ember 强调色，分数保留语义色。
> 关联：[前端规范](./frontend.md)
>
> **选型结论**：选择 shadcn-vue，而不是 Element Plus / Ant Design Vue / PrimeVue 这类全量组件库，原因是 OfferCoach 的面试间、流式反馈与报告页需要强定制，且现有前端已经是同一路线。Dialog 等交互原语直接使用 Reka UI，保证焦点管理与无障碍；不引入第二套设计语言。

## 1. 设计原则

1. **专注答题**：面试房间只保留题目、作答、进度与反馈，减少装饰与跳转。
2. **证据优先**：分数必须配原文引用与具体建议，不用“很棒/再接再厉”这类空话。
3. **进度可见**：任何超过 1 秒的等待都有骨架、进度或阶段文案；流式输出必须可中断。
4. **克制的专业感**：中性底色 + 单一品牌色，分数用语义色，避免“游戏化”过度。
5. **移动可用**：面试房间在 375px 宽度可完成全部操作，不依赖 hover。

## 2. Design Tokens

### 2.1 颜色

采用 HSL CSS 变量，便于暗色模式与透明度组合。

| Token | 浅色 | 深色 | 用途 |
|---|---|---|---|
| `--bg` | `214 20% 97%` | `220 20% 5%` | 页面背景 |
| `--surface` | `0 0% 100%` | `218 19% 9%` | 卡片、面板 |
| `--surface-2` | `214 22% 95%` | `218 19% 13%` | 次级背景、代码块 |
| `--border` | `216 16% 89%` | `217 15% 20%` | 分割线、输入框 |
| `--text` | `215 30% 9%` | `213 20% 94%` | 正文 |
| `--text-2` | `214 16% 32%` | `215 13% 72%` | 次级文本 |
| `--muted` | `214 10% 42%` | `214 10% 56%` | 辅助文字 |
| `--brand` | `215 30% 9%` | `213 20% 94%` | 主操作、选中态（近黑/近白） |
| `--brand-foreground` | `0 0% 100%` | `220 20% 7%` | 主色上的文字 |
| `--accent` | `14 60% 41%` | `20 68% 62%` | 数据高亮、雷达图、中高分数 |
| `--success` | `152 38% 40%` | `152 45% 55%` | 高分、成功 |
| `--warning` | `36 62% 45%` | `38 65% 58%` | 中等分、注意 |
| `--danger` | `4 55% 48%` | `4 65% 62%` | 低分、错误、删除 |
| `--info` | `214 24% 45%` | `214 20% 62%` | 提示、链接 |
| `--overlay` | `220 25% 8%` | `0 0% 0%` | 弹层遮罩 |

**语义色规则**：

- 分数 ≥ 8.5：`success`；7.0–8.4：`accent`；6.0–6.9：`warning`；< 6.0：`danger`。
- 颜色不能是唯一信息：分数必须显示数字，进度必须显示百分比。
- 主色是中性黑/白，承担主操作与选中态；ember `accent` 只做数据强调，避免整页多彩。

### 2.2 字体

```css
--font-sans: system-ui, -apple-system, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif;
--font-mono: "Cascadia Mono", "SF Mono", Consolas, ui-monospace, monospace;
```

| Token | 字号/行高 | 字重 | 用途 |
|---|---|---|---|
| `text-3xl` | 30/38 | 600 | 报告总分、营销标题 |
| `text-2xl` | 24/32 | 600 | 页面标题 |
| `text-xl` | 20/28 | 600 | 区块标题 |
| `text-base` | 16/24 | 600 | 卡片标题 |
| `text-sm` | 14/20 | 400 | 正文 |
| `text-xs` | 12/18 | 400 | 辅助说明、标签 |
| `text-2xs` | 12/16 | 500 | 密集元数据（角标、导航副标题） |
| `text-3xs` | 11/16 | 500 | 仅简历版式预览与极密元数据 |

- 产品正文最小 12px；移动端正文 16px（防 iOS 缩放）。`text-2xs/3xs` 不得用于普通正文或错误提示。
- 数字使用 `font-variant-numeric: tabular-nums`，分数与计时不跳动。
- 语义色分「填充色」与「文本色」：文本一律 `*-strong`；`success/warning/accent` 原色只用于图标、圆点、描边与背景填充。

## 3. 组件库策略

- **基座**：shadcn-vue（源码复制到 `components/ui`，基于 Reka UI + Tailwind）。
- **理由**：可访问性由 Reka UI 保证；样式完全可控；无运行时主题包；按需引入体积小。
- **约束**：`components/ui` 只做通用原子组件，不含业务逻辑；业务组件放 `features/*/components` 或 `components/common`。
- **Storybook**：所有 `ui` 组件与核心业务组件必须有 stories，覆盖默认/禁用/加载/错误/暗色。
- **图标**：lucide-vue-next，统一 16/20/24 三档；不使用 emoji 作为功能图标。

## 5. 核心组件规格

### 5.1 Button

| 属性 | 取值 |
|---|---|
| variant | `primary`（品牌底白字）、`secondary`（浅底深字）、`outline`（描边）、`ghost`（无底）、`danger`（红底） |
| size | `sm` 32px、`md` 40px、`lg` 48px |
| 状态 | hover 亮度 -4%、active 缩放 0.98、focus 焦点环、loading 左侧 spinner + 禁用 |
| 规则 | 一屏最多 1 个 primary；危险操作必须 `danger` + 二次确认 |

### 5.2 ScoreRing

```text
Props: score(0–100), size(120|160|200), label, animated
颜色: 按语义色分段
内容: 中心大号分数 + 下方“总分”说明
动效: 首次进入 600ms 从 0 到目标值，respect reduced-motion
```

- 分数变化时才动画；刷新页面不重复动画。
- 无分数（报告生成中）显示 `—` 与骨架，不显示 0。

### 5.3 StreamingFeedback

**状态机**：`idle → connecting → streaming → done | error`

| 状态 | UI |
|---|---|
| connecting | 三点跳动 + “正在连接面试官…”；超过 3s 显示“切换线路” |
| streaming | 文本逐段出现；右上角“停止”；底部显示当前区块（优点/改进/改写） |
| done | 显示五维分数、证据引用、改写建议；提供“复制建议” |
| error | 显示可读原因 + “重试评分”；不重复扣额度提示 |
| degraded | 顶部黄色提示“当前为精简反馈模式” |

**结构**：

```text
┌──────────────────────────────────────────┐
│ 本题反馈                    停止 ✕      │
│ 总分 8.1  ●●●●●●●●○○                    │
│ 优点                                     │
│  • 背景交代清楚，先给结论再展开           │
│  • 引用了 QPS 从 800 到 2400 的量化结果   │
│ 改进                                     │
│  • 技术取舍缺少替代方案对比               │
│ 建议改写（可复制）                        │
│  “……”                                    │
│ 证据                                     │
│  “QPS 从 800 提升到 2400”                │
└──────────────────────────────────────────┘
```

- 流式期间只渲染纯文本；结束后再做 Markdown 渲染与代码高亮。
- 证据引用高亮显示，点击可定位到回答原文（若仍在当前页）。
- FREE 套餐隐藏“建议改写”区块；PRO 上线后才渲染。
- 文本追加节流 50ms；自动滚动到底部，但用户上滚后暂停自动滚动。

### 5.4 QuestionCard + AnswerEditor

- 题号、维度 Badge、难度 Badge、“为什么问这题” Tooltip/折叠说明。
- 计时环在右上角；剩余 30s 变警告色，归零自动提交或提示（按配置）。
- 回答框：默认 8 行，自动增高至 16 行；显示字数 `123 / 4000`。
- 草稿状态：“已保存草稿 · 10:32”，不打断输入。
- 提交按钮固定底部；未满 10 字禁用并提示。
- 提交后按钮进入 loading，防止双击；成功后滚动到反馈面板。

### 5.5 UploadDropzone

| 状态 | 展示 |
|---|---|
| idle | 虚线框、上传图标、“拖拽或点击上传 PDF/DOCX” |
| dragover | 品牌色描边 + 浅色底 |
| uploading | 文件名 + 进度条 + 取消 |
| parsing | 步骤条：上传 → 解析 → 结构化 |
| error | 红色提示 + 重试 + 支持格式说明 |
| success | 文件卡片 + “查看解析结果” |

- 前端校验：类型、大小；错误文案具体（“文件 12.4MB，超过 10MB 限制”）。
- 上传中禁止再次选择；失败可重试，不重复扣额度。

### 5.6 DataTable（管理端）

- 功能：排序、筛选、分页、列显隐、批量选择、行操作。
- 空态、加载骨架、错误重试必须具备。
- 长文本截断 + Tooltip；状态用 Badge。
- 批量操作需显示选中数量与影响范围。
- 表格在 < 768px 转为卡片列表，不横向滚动关键操作。

## 7. 交互状态规范

| 状态 | 要求 |
|---|---|
| Loading | 首屏用骨架；局部用 spinner；超过 3s 显示阶段文案；超过 10s 提供取消 |
| Empty | 说明为什么空 + 一个明确动作（上传/新建/去练习） |
| Error | 可读原因 + 重试 + 请求 ID（可复制）；不展示堆栈 |
| Disabled | 降低透明度并说明原因（Tooltip 或辅助文字） |
| Success | Toast 或页内反馈，2–4s 自动消失；关键结果不只用 Toast |
| Streaming | 可中断、可重连、自动滚动可暂停 |
| Offline | 顶部条提示“网络已断开”，恢复后自动重试非计费请求 |

### 7.1 跨页面交互铁律

1. **写操作以服务端结果为准**：成功后失效相关 query 并回查；不得只弹 toast 就当成功。
2. **破坏性操作二次确认**：删除简历、注销账号、放弃会话必须确认；确认文案写清影响面，不只写“确定吗”。
3. **列表三态齐全**：loading 骨架、empty 说明 + 动作、error 可重试；不得只做成功态。
4. **弹窗只做一件事**：标题写清对象与动作；焦点陷阱、ESC 关闭、关闭后焦点回到触发器。
5. **行内操作不超过 3 个**：超出收进“更多”菜单；危险动作红色且与普通动作区分；同一行不得并排两个同色危险按钮。
6. **表格数字右对齐、等宽数字**；金额单位写在表头或列名，不在每个单元格重复“元”。
7. **时间显示相对 + 绝对**（“3 分钟前（10:32）”）；时区跟随用户设置。
8. **流式反馈可停止、可重连**；用户上滚后暂停自动滚动；结束后再渲染 Markdown，流式期间用纯文本。
9. **表单错误定位第一个字段**；提交中禁用按钮；前端校验只是体验，服务端仍必须校验。
10. **无障碍**：图标按钮有 `aria-label`；流式区域用摘要级 `aria-live`，不逐字播报；键盘可完成关键路径。
11. **移动端点击区域 ≥ 44×44px**；不依赖 hover 才出现操作。
12. **文案克制**：不承诺“保证通过/提升 10 倍”，不羞辱用户；错误文案包含“发生了什么 + 怎么办”。

## 8. 响应式断点

| 断点 | 宽度 | 布局 |
|---|---|---|
| `sm` | ≥ 640 | 两列卡片 |
| `md` | ≥ 768 | 侧边栏可折叠 |
| `lg` | ≥ 1024 | 标准桌面布局 |
| `xl` | ≥ 1280 | 通用桌面宽屏 |
| `room` | ≥ 1400 | 面试房间三栏（240 / 主区 / 400） |
| `2xl` | ≥ 1536 | 内容最大宽度 1280，居中 |

- 面试房间在 `room` 以下为单列：题目导航横向滚动、反馈在答题区下方；`room` 以上才固定三栏。1280–1399 禁止压缩主答题区到 400px 以下。
- 管理端表格在 `md` 以下转卡片。
- 触控目标 ≥ 44×44px；移动端 `sm` 按钮、Toast 关闭、底部导航抬到 44px，且不依赖 hover。

## 9. 暗色模式

- 通过根节点 `.dark` 切换；跟随系统或用户设置，存 `localStorage`（仅偏好，不含敏感信息）。
- 暗色下不使用纯黑；背景 `220 20% 5%`，卡片 `218 19% 9%`。
- 语义色提高亮度，保证对比度；图表网格线降低不透明度。
- 图片/头像在暗色下加 1px 边框，避免融入背景。
- 打印/PDF 始终使用浅色主题。

## 10. 文案规范

- 用第二人称、动词开头：“上传简历”“开始模拟面试”。
- 错误文案包含“发生了什么 + 怎么办”：“文件超过 10MB，请压缩后重试”。
- 不使用夸张承诺：“提升 10 倍”“保证通过”禁止出现。
- 分数解释用中性词：“建议加强”“可补充”，避免“很差”“不合格”。
- 时间用相对 + 绝对：“3 分钟前（10:32）”。
- 空状态避免卖萌；保持专业与简洁。
- 产品副标题统一「模拟面试」/「面试练习与复盘」，不强调「AI」字样。

## 11. Storybook 与交付

- 目录与组件同构：`ui/Button`、`features/interview/StreamingFeedback`。
- 每个 story 至少包含：Default、Loading、Error、Dark、Mobile（适用时）。
- 使用 MSW mock API；流式组件提供“逐字播放”控制器，便于视觉验收。
- 设计变更先改 Token，再改组件，最后改页面；禁止页面级硬编码覆盖。
- 交付清单：Figma/线框、Token 表、组件 stories、交互说明、可访问性检查结果。
