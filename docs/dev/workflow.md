# 开发流程与契约管理

> 状态：生效 ｜ 版本：v1.1 ｜ 更新：2026-11-07
> 适用：前端先行、AI 独立服务、后端多模块单体的开发模式。
> 关联：[conventions.md](conventions.md)、[../design/api.md](../design/api.md)、[../design/architecture.md](../design/architecture.md)

## 1. 总流程

```text
需求登记（R-ID + 验收标准）
  → 设计（ADR / 数据模型 / API 骨架）
  → 契约骨架（资源、URL、方法、信封、错误码、鉴权）
  → 前端 UI（类型从 OpenAPI 生成；数据来自 mock 或真后端）
  → 字段契约定稿（UI 完成后）
  → 后端实现（按定稿契约）
  → 自测（单测 + Testcontainers + .http + AI 评测冒烟）
  → 联调（只处理契约理解偏差）
  → 测试 / UAT / 压测 / 安全
  → 发布（tag → CI → 灰度）
  → 文档与 CHANGELOG 同批更新
```

每个需求必须有 R-ID（[requirements.md](../requirements.md)）、负责人、验收标准；没有验收标准的需求不进入开发。

## 2. API 契约的两层

| 层 | 内容 | 何时定 | 会被 UI 改变吗 |
|---|---|---|---|
| 骨架层 | 资源划分、URL、HTTP 方法、统一错误信封、分页、错误码、鉴权头、SSE 事件 | 前端动工前 | 基本不会；描述资源组织，与页面长相无关 |
| 字段层 | 每个接口的具体出入参字段、类型、枚举、可空性 | UI 开发中演进，模块完成时定稿 | 会；画页面的过程就是发现数据需求的过程 |

骨架层全局约定见 [../design/api.md](../design/api.md) §1；模块只补资源级路径与字段。

**冻结规则**：

1. **冻结点 = 后端动工时**，不是前端动工时。前端开发期间字段可改，但只改 `api/` 类型与 mock，不改页面业务逻辑。
2. 后端动工后字段不再随意改。确需变更走三步：**先改契约文档 → 再改前端类型/mock → 后端按新版实现**。
3. 禁止后端实现时私自偏离契约；联调返工的成本高于提前改文档。
4. 破坏性变更（删字段、改类型、收紧枚举）必须升 `/api/v2` 或在发布说明中声明迁移窗口。

## 3. 契约载体

| 载体 | 内容 | 权威性 |
|---|---|---|
| OpenAPI | Java（springdoc）与 Python（FastAPI）合并为 `openapi.bundle.json` | 机器可读契约；CI 用 `oasdiff` 检查破坏性变更 |
| 前端类型 | `openapi-typescript` 生成 `src/api/generated/` | 唯一 DTO 类型来源；禁止手写同名类型 |
| 数据模型 | [../design/data-model.md](../design/data-model.md) 的 DDL 与字段说明 | 表结构权威；实体与 DTO 对照它 |
| AI 内部接口 | Python `/internal/v1/**` 的 OpenAPI + 请求/响应样例 | 服务间契约；双端契约测试 |
| SSE 协议 | [../design/api.md](../design/api.md) §7 的事件表 | 前后端共同遵守；事件名/字段变更需双端同步 |

- 所有契约变更必须同时更新 OpenAPI 与文档；只改代码不改契约视为未完成。
- 内部接口不暴露公网；网关拒绝 `/internal/**` 入站。

## 4. 前端开发的数据来源

| 阶段 | 数据来源 | 说明 |
|---|---|---|
| 纯 UI 开发 | MSW / 本地 mock | 覆盖 loading、empty、error、慢请求、SSE 分块；mock 必须与契约字段一致 |
| 联调前 | 真后端（已就绪模块）+ mock（未就绪模块） | 按模块登记切换；禁止在组件里写分支 |
| 联调 | 真后端 + staging AI | AI 服务可用固定回放，避免不确定性与费用 |
| E2E | staging + 录制回放 | 另设 1 条真实 AI 冒烟 |

- 前端只通过 `src/api/client.ts` 请求；mock 与真后端切换在 client/baseURL 层完成，页面零改动。
- 禁止把 mock 数据写进生产 bundle；mock 只用于开发与测试。

## 5. 后端实现与自测

每个端点交付物：**Controller 方法 + Service 业务方法 + DTO**；Entity/Mapper 是持久层薄件。

**自测门槛（未通过不进入联调）**：

1. `.http` / Postman 脚本覆盖成功、校验失败、无权限、资源不存在、状态冲突。
2. Service 业务规则最小单测：状态机、额度、幂等、评分加权、上下文裁剪。
3. Testcontainers 集成：PG + Redis + MQ；关键路径真实依赖。
4. 契约自测：OpenAPI 响应 Schema 校验；字段名/类型/可空性与文档一致。
5. AI 相关：黄金集 20 条冒烟；JSON 合法率 100%；安全用例通过。
6. 日志/指标：请求有 `requestId`、`traceId`；关键路径有耗时与错误码。

自测清单详见 [backend.md](backend.md) §17。

## 6. 联调纪律

- 联调只处理“双方对契约理解不一致”；功能 bug 在自测阶段解决。
- 联调问题必须记录：请求样例、响应、期望、契约条款；修完补契约测试。
- 不允许用“前端先兜底/后端先兼容”长期绕过契约；临时兜底必须登记待办与删除时间。
- AI 输出不确定：联调断言结构、范围、引用存在性，不断言具体措辞。

## 7. 测试与发布

| 阶段 | 门槛 |
|---|---|
| PR | lint + typecheck + unit + 契约 diff + 安全扫描 |
| 合并 | 1 次独立 review；无 P0/P1 未决 |
| staging | E2E 主干 + 压测冒烟 + AI 评测 + 迁移演练 |
| 灰度 | 10% 流量 30 分钟；错误率、TTFT、成本、报告成功率达标 |
| 全量 | 监控 24h；回滚镜像与开关可用 |
| 发布后 | CHANGELOG 更新；文档与代码同批；遗留项登记 |

详细门禁见 [testing.md](testing.md) 与 [../ops/ci-cd.md](../ops/ci-cd.md)；分支、尺寸、评审与合并规则见 [pr-workflow.md](pr-workflow.md)。

## 8. 交付六阶段（产品上线视角）

| 阶段 | 目标 | 准出物 |
|---|---|---|
| 1 启动与诊断 | 锁定范围、用户与场景 | 范围说明、需求索引、验收口径 |
| 2 蓝图设计 | 业务链路、数据模型、接口骨架、页面原型 | 设计文档、ADR、待决清单 |
| 3 开发实现 | 功能可用、配置就绪 | 可运行构建、种子数据、契约 |
| 4 测试与 UAT | 业务视角验收 | 测试报告、缺陷清单、UAT 结论 |
| 5 上线切换 | 生产可用 | 上线记录、迁移核对、回滚预案 |
| 6 验收与移交 | 可自主运营 | 验收单、运维手册、遗留清单、复盘 |

每阶段准出未达成不进入下一阶段；范围变更走“一次一条决策”，先分析影响再拍板。

## 9. 变更与决策

| 类型 | 载体 | 规则 |
|---|---|---|
| 架构/技术选型 | ADR（[architecture.md](../design/architecture.md)） | 写背景、选项、结论、代价；被替代的 ADR 标记 `Superseded` |
| 跨服务/破坏性 API | RFC / PR 描述 | 影响面、迁移方案、回滚方案、双端排期 |
| 数据库破坏性变更 | Flyway expand-contract | 先加列/表 → 双写回填 → 删旧；同一发布不做破坏性操作 |
| 未定事项 | [README.md](../README.md) §4 | `> 待决：` + D-ID；确定后写入正文并删除条目 |
| 一次性复查 | `reviews/` | 只留档；结论回写 design/dev |

## 10. 阶段收尾

- 种子数据：演示账号、2 份简历、2 个 JD、1 场已完成报告，供验收与演示。
- 部署演练：按 [../ops/deployment.md](../ops/deployment.md) 在 staging 走一遍；暴露环境问题。
- 契约复盘：列出“后端动工后仍改契约”的条目，分析原因并修订流程。
- 文档复盘：检查索引、状态、待决清单、CHANGELOG 是否同步；未同步视为未完成。
