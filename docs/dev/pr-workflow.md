# PR 提交流程与硬性限制

> 状态：生效 ｜ 版本：v1.0 ｜ 更新：2026-11-09
> 适用：所有代码、配置、迁移与文档变更。
> 关联：[conventions.md](conventions.md) §1–2、[workflow.md](workflow.md) §7、[../ops/ci-cd.md](../ops/ci-cd.md)。

## 0. 一页结论

1. `main` 受保护，**任何变更都必须走分支 + PR**；禁止直接 push、禁止自审自合。仓库设置强制 PR、两项 CI、分支最新与 squash-only。
2. **一个 PR 只做一件事**；功能、重构、格式化、依赖升级不得混在一起。
3. PR 有**尺寸硬上限**；超出先拆分，不接受“顺手改一点”。
4. 合并前必须满足：CI 全绿 + 至少 1 次独立 review + 无未决 P0/P1 + 分支已同步 `main`。
5. 统一 **squash merge**，合并后删除分支；PR 合并不等于上线，发布另走 [ci-cd.md](../ops/ci-cd.md) 与 [deployment.md](../ops/deployment.md)。
6. 代码相关的迁移、配置项、行为变化必须同 PR 更新文档与 CHANGELOG；纯文档主题单独开 PR。只改代码视为未完成。
7. 禁止提交密钥、真实简历、未脱敏用户数据；发现即关闭 PR 并轮换凭据。

## 1. 角色与职责

| 角色 | 职责 |
|---|---|
| 作者 | 拆分任务、自测、填写 PR 模板、响应评审、合并前同步主线 |
| 独立评审 | 不参与该 PR 实现；检查正确性、边界、安全、测试与文档；给出明确结论 |
| 合并者 | 核对门禁与审批有效性；执行 squash；确认合并后状态 |

- 独立评审可由团队成员或独立审查代理完成；代理结论必须保留原始审查记录，并由合并者复核后记录在 PR。
- 作者不能批准自己的 PR；不得由作者本人运行评审代理后自行填写“通过”。
- 同一人不能同时充当唯一评审与合并者。
- 高风险 PR（§4）需要 2 次独立评审，其中至少 1 次聚焦安全/数据。

## 2. 提交前

1. 从最新 `main` 拉分支，命名遵循 `feat/`、`fix/`、`chore/`、`docs/`、`refactor/`、`hotfix/`。
2. 本地跑完整门禁，不允许“等 CI 再说”。

| 范围 | 命令 |
|---|---|
| 后端 | `cd backend && mvn -q spotless:apply && mvn -q verify` |
| 前端 | `cd frontend && pnpm install --frozen-lockfile && pnpm check` |
| 文档 | 检查链接、命令、版本号、索引与 CHANGELOG |

3. 自审 diff：删除调试代码、无关格式化、临时文件与本地配置。
4. 行为/配置/接口/迁移变化：同批更新相关文档；新增配置必须在 `application.yml` 有默认值或明确必填说明。
5. 数据库变更：新增迁移文件，不修改已执行迁移；先备份，遵循 expand-contract。

## 3. PR 创建

- 标题格式：`<type>(<scope>): <中文简述>`，≤ 50 字；`type` 与提交规范一致。
- 必须使用 `.github/pull_request_template.md`，不得留空关键项。
- 必须写清：变更内容、关联 R-ID/Issue/D-ID、验证证据、风险与回滚、数据/迁移、安全与隐私。
- 未完成时用 Draft PR；禁止用“先合并再补测试/文档”换速度。
- 标签：`size:large`（超尺寸例外）、`risk:high`（高风险）、`hotfix`、`dependencies`、`docs`。

## 4. 硬性限制

| 项 | 限制 | 超出处理 |
|---|---|---|
| 主题 | 1 个 PR = 1 个需求/缺陷/文档主题 | 拆分；重构与新功能分开 |
| 常规代码量 | 源码新增+删除 ≤ 400 行，且源码文件 ≤ 15 个 | 拆分 |
| 总变更量 | 含文档/锁文件/生成物 ≤ 1200 行、≤ 40 个文件 | 拆分 |
| 尺寸例外 | 单 PR 源码最多 800 行/30 文件，且必须 `size:large` + 仓库所有者批准 | 超过该例外上限必须拆分，禁止用例外夹带重构 |
| 框架大版本升级 | 仅限依赖/框架升级，源码 ≤1200 行/40 文件；所有者批准 + 2 次评审 | 超过按模块拆成多个 PR |
| 纯文档 PR | ≤ 800 行；不得夹带代码/配置 | 拆分 |
| Hotfix | ≤ 150 行源码、≤ 5 个文件 | 只修故障点，后续补根因修复 |
| 评审 | 常规 1 次独立评审；高风险 2 次 | 未达标不合并 |
| CI | 最新 commit 上全部 required checks 通过 | 失败即阻断；禁止靠重跑掩盖 flaky |
| 分支 | 合并前已同步最新 `main` | behind 时更新分支并重跑 CI |
| 审批有效性 | 新 push 后旧 approval 失效 | 重新评审 |
| 文档 | 行为/配置/接口/迁移变化同 PR 更新 | 缺文档视为未完成 |
| 迁移 | 新文件、可回滚演练、已备份 | 破坏性变更单独 PR + 方案 |
| 密钥 | 不出现任何真实密钥/域名/IP/用户数据 | 立即关闭并轮换 |

**高风险范围**：认证/会话、权限与管理端、额度/邀请、AI 路由与 Prompt、数据库迁移、部署/CI、 secrets、简历/JD 原文处理。

- 尺寸统计排除：`pnpm-lock.yaml`、生成类型/客户端、快照、`target/`、`dist/`、二进制素材；迁移与配置计入源码。
- 不接受“格式化整个文件”制造大 diff；先单独格式化 PR。

## 5. 评审规则

- 首次响应 ≤ 24 小时；返工后复审 ≤ 48 小时；7 天无实质进展关闭或转为 Draft。
- 评论必须带优先级：`P0` 阻断、`P1` 合并前修复、`P2` 可后续、`nit` 可选。
- P0/P1 未解决不得合并；P2 必须建 Issue 或登记待办，不能口头略过。
- 评审至少覆盖：边界与错误路径、并发/幂等、权限与越权、日志与隐私、测试有效性、回滚可行性。
- 不以“CI 过了”替代人工判断；CI 只证明可构建与既有测试通过。

## 6. 合并与发布

1. 确认 required checks 在最新 commit 全绿，审批未被新提交失效。
2. 使用 **Squash and merge**；标题符合 Conventional Commits；不产生 merge commit。
3. 合并后删除远端分支；本地同步 `main`。
4. 发布不在 PR 内自动发生：按 [ci-cd.md](../ops/ci-cd.md) 构建明确版本镜像，按 [deployment.md](../ops/deployment.md) 备份、迁移、验证与记录。
5. 合并后 24 小时内回写遗留项与发布记录；CHANGELOG 已在同 PR 更新，不重复补。发现回归按发布流程回滚，不直接改 `main` 热修。

## 7. 例外

| 场景 | 允许的放宽 | 仍必须满足 |
|---|---|---|
| 线上故障 hotfix | 尺寸 ≤150 行，可 1 次评审 | 同套 CI、备份、回滚方案、48h 内复盘；涉及高风险范围仍需 2 次评审 |
| 依赖机器人 | 可批量文件 | CI 全绿；major 升级需人工验证并写风险 |
| 纯文档 | 可 1 次评审 | 链接/命令/版本准确，不夹带代码 |
| 框架大版本升级 | `size:large` | 所有者批准、2 次评审、完整回归与回滚镜像 |

**不得放宽**：直接 push `main`、自审自合、跳过测试、修改已执行迁移、提交密钥、绕过权限/安全审查。

## 8. 检查清单

**作者**

- [ ] 一个主题；尺寸在限制内或已批准 `size:large`
- [ ] 本地后端/前端门禁通过；关键路径有测试
- [ ] 文档、配置默认值、CHANGELOG 已同步
- [ ] 迁移已备份并演练；回滚方案已写
- [ ] 无密钥、真实用户数据、调试代码、无关格式化

**评审**

- [ ] 正确性与边界；并发/幂等；权限/越权
- [ ] 测试能证明行为，不是只跑通
- [ ] 日志不含 PII；错误码与文案一致
- [ ] 兼容旧版本/旧 Schema；回滚可行
- [ ] 结论明确：批准 / 要求修改 / 阻断

**合并者**

- [ ] required checks 绿；审批针对最新 commit
- [ ] 分支已同步 `main`；无未决 P0/P1
- [ ] squash 标题规范；合并后删除分支
- [ ] 需要发布时已登记版本、迁移与验证结果
