## 1. 范围与假设

**MVP 范围**：账号、简历解析、JD 匹配、8 题文字面试、流式评分、报告、题库/Prompt/日志管理、免费额度。

**不在 MVP**：语音作答、追问、支付、PDF 导出、第三方登录、URL 抓取、人群对比。

**假设**：

- 团队熟悉 Spring Boot 与 Vue；Python 由 AI 工程师负责。
- 题库冷启动由运营提供 300 题 + AI 生成 200 题，人工审核后入库。
- LLM 供应商账号与额度在第 1 周就绪；否则用本地小模型先联调。
- 设计稿在第 2 周前完成核心 5 个页面。

## 4. 关键路径

```text
T0.2 后端骨架 → T0.5 库表 → T1.1 上传 → T1.3 结构化
  → T2.3 题库索引 → T2.4 检索 → T2.5 出题 → T3.1 回答/上下文
  → T3.3 评分 Prompt → T3.4 SSE → T3.6 网关 → T4.1 报告任务
  → T4.3 Worker → T6.2 压测 → T6.9 上线
```

**风险最高的三处**：

1. T2.3–T2.5（题库与出题质量）：依赖题库冷启动与向量化环境。
2. T3.3–T3.4（评分流）：契约与解析状态机容易反复。
3. T4.1–T4.3（异步报告）：Outbox/MQ/幂等联调耗时。

## 5. 并行策略

- W1：BE 做骨架/账号，FE 做工程/登录页，AI 做供应商连通性与 Prompt 雏形。
- W2：BE 做上传/额度，AI 做解析，FE 做上传/修正页；JD 匹配稍后并行。
- W3：BE 做会话，AI 做题库/检索，FE 做房间布局；出题联调在周末前完成。
- W4–W5：BE 做提交/回写，AI 做评分流，FE 做编辑器/反馈；每日一次联调。
- W6：BE 做报告/额度，AI 做报告生成，FE 做报告页；QA 开始写 E2E。
- W7：管理端前后端并行；AI 做评测与索引更新。
- W8：全员硬化，停止加需求。

## 7. Definition of Done

**单个任务**：

- 代码已评审并合并；有单测/集成测试；错误码与日志齐全。
- 接口变更同步 OpenAPI 与前端类型；无破坏性未声明变更。
- 自测通过，附截图/录屏/日志；文档更新。

**里程碑**：

- 功能按 AC 验收；P0/P1 为 0。
- 性能指标达标或有批准的例外。
- 监控、告警、Runbook 覆盖新增能力。
- 演示脚本可完整跑通。

**发布**：

- [testing.md](./testing.md) 门禁全过；灰度 3 天无 P0/P1。
- 回滚演练成功；值班与告警就绪。
- 隐私政策、用户协议、数据删除入口上线。

## 9. 面试演示脚本（5 分钟）

1. **30s 背景**：上传简历 + JD，生成针对性面试，逐题评分并出报告。
2. **60s 输入**：展示简历解析与低置信字段修正；展示 JD 匹配证据。
3. **90s 核心**：创建 8 题面试 → 答一题 → 展示流式反馈首字时间与停止/重连。
4. **60s 报告**：雷达图、逐题证据、改进计划；强调总分由代码计算。
5. **60s 管理端**：题库来源、Prompt 版本、灰度实验、调用日志与成本。
6. **30s 数据**：首字 P95、Recall@5、单场成本、完成率；说明降级与防刷。
7. **30s 复盘**：讲一个取舍（如“为什么网关直连 AI 服务”“为什么 Prompt 权威实现只保留在 Python”）。

**演示前检查**：

- 预置 2 份简历、2 个 JD、1 场已完成报告，避免现场等待。
- 关闭无关通知；准备离线录屏作为兜底。
- 不展示真实用户数据与密钥；不承诺录用结果。
