# 产品需求（PRD）

> 状态：评审中 ｜ 版本：v1.1 ｜ 更新：2026-11-07
> 需求索引见 [requirements.md](../requirements.md)；关联：[架构](./architecture.md)、[接口](./api.md)

## 1. 背景与问题

求职者在面试前普遍缺少**针对性、可量化、低成本**的练习反馈：

- 通用题库与目标 JD 脱节，练了但用不上。
- 找人模拟面试成本高、时间难约、反馈主观且不可复盘。
- 简历问题（项目描述空泛、技能与 JD 不匹配）往往在投递后才发现。
- 现有 AI 产品多为“一次性问答”，缺少会话上下文、结构化评分与可执行改进计划。

OfferCoach 把「简历 + JD」作为输入，生成**岗位针对性**的模拟面试，逐题评分，最终产出可复盘的面试报告与改进计划。

## 2. 目标与非目标

### 2.1 产品目标

1. 用户 10 分钟内完成一场 8 题模拟面试，并拿到可执行的改进建议。
2. 评分与建议必须**引用用户回答原文**作为证据，拒绝空泛点评。
3. 面试问题必须与目标 JD 的技能要求有可追溯的匹配关系（可查看“为什么问这题”）。
4. 单场 AI 成本可控、可审计，防止刷量与滥用。

### 2.2 非目标（本期不做）

- 不做真实企业内推、投递、猎头撮合。
- 不做视频面试与表情识别。
- 不做多人群面、实时语音对话（V1 仅支持录音转写）。
- 不做简历代写、代投。
- 不做跨境支付与发票系统（MVP 使用模拟支付）。

## 4. 核心用户旅程

### 旅程 A：首次体验（目标 < 12 分钟）

1. 注册/登录（邮箱或手机号 + 验证码）。
2. 上传简历（PDF/DOCX），等待解析（P95 < 8s），可修正结构化字段。
3. 粘贴目标岗位 JD，系统展示“匹配度 + 缺口技能”。
4. 选择面试配置（题量、难度、面试官风格），消耗 1 次额度。
5. 进入面试间，逐题作答；每题提交后流式返回评分与改进建议。
6. 完成全部题目，异步生成报告；完成后站内通知并可查看/导出 PDF。

### 旅程 B：复盘提升

1. 在历史报告中按维度查看分数趋势。
2. 打开单题详情，对比“我的回答 / 建议改写 / 参考答案要点”。
3. 将改写的回答加入“我的语料库”，下一场面试可选择复用。
4. 针对薄弱维度发起“专项练习”（V1.1）。

### 旅程 C：运营配置

1. 管理员导入题库（CSV/JSONL），批量向量化。
2. 新建 Prompt 版本，跑离线评测，达标后灰度 10%。
3. 观察 48 小时指标（评分分布、TTFT、成本、投诉率），全量或回滚。
4. 在调用日志中按用户/会话/模型检索异常。

## 6. 功能详述与业务规则

### 6.1 账号与鉴权

- 注册需通过图形验证码 + 邮箱/短信验证码（MVP 用邮件，开发环境打印到日志）。
- 密码至少 8 位，包含字母与数字；服务端 Argon2id 哈希。
- 登录失败 5 次锁定 15 分钟（Redis 计数，按账号 + IP 双维度）。
- Access Token 15 分钟，Refresh Token 7 天、单次使用后轮换；检测到重放则吊销该用户全部会话。
- 注销账号：立即禁用，7 天后删除用户内容（简历/JD/回答/报告/对象存储）并匿名化账号标识；审计与财务流水按法定期限保留。

### 6.2 简历上传与解析

| 规则项 | 约束 |
|---|---|
| 格式 | PDF、DOCX；不接受图片、压缩包、可执行文件 |
| 大小 | ≤ 10 MB |
| 页数 | ≤ 20 页 |
| 文本量 | 解析后 ≥ 200 字符；不足则走 OCR |
| 安全 | MIME 嗅探 + 扩展名双校验；ClamAV 扫描；随机文件名；私有桶 |
| 解析时限 | 单份 P95 < 8s，超时 30s 标记 FAILED 并返还解析额度 |
| 结构化字段 | 基本信息、教育、工作、项目、技能、证书、自我评价 |
| 置信度 | 每个字段带 `confidence`；低于 0.6 的字段在 UI 高亮要求确认 |
| 保留 | 原文件与解析结果保留 180 天；用户删除后 24h 内清理对象存储与向量 |

**业务规则**：

1. 解析失败自动重试 1 次（换轻量模型），仍失败则提示手动粘贴文本。
2. 用户修改结构化字段后，重新生成简历摘要与匹配向量，旧缓存立即失效。
3. 同一用户最多保留 5 份简历，超出需删除旧文件。

### 6.3 JD 与匹配分析

- 粘贴文本长度 50–8000 字符；去除 HTML 标签与不可见字符。
- 结构化字段：职位、公司、职级、职责、必备技能、加分技能、技术栈、关键词。
- 匹配分析输出：总匹配度（0–100）、已匹配技能、缺口技能、建议补强点、匹配证据（简历原文片段 ↔ JD 原文片段）。
- 匹配度只作为参考，不参与面试总分；不得展示“保证通过”等承诺性文案。

### 6.4 面试会话

| 配置项 | 取值 | 默认 |
|---|---|---|
| 题量 | 5 / 8 / 10 / 12 | 8 |
| 难度 | EASY / MIXED / HARD | MIXED |
| 面试官风格 | 温和 / 标准 / 压力 | 标准 |
| 作答方式 | TEXT / VOICE | TEXT |
| 单题时限 | 60–300 秒 | 180 秒 |
| 语言 | zh-CN / en-US | zh-CN |

**题目结构规则（8 题默认）**：

- 维度配比：专业深度 3、项目经历 2、行为面试 2、岗位匹配 1。
- 难度阶梯：简单 2、中等 4、困难 2；第 1 题必须是简单题，降低冷启动压力。
- 至少 60% 题目来自 RAG 题库，且每题记录检索来源；不足时用生成题补足并标记 `source=GENERATED`。
- 同一用户 30 天内不重复出已答过的题（题库不足时允许重复，但需换问法）。

**状态机**：

```
CREATED → PREPARING → READY → IN_PROGRESS → FINISHED → REPORT_GENERATING → COMPLETED
                ↘ FAILED（出题失败，返还额度）          ↘ REPORT_FAILED（可重试）
IN_PROGRESS → ABANDONED（24h 无操作，不返还额度）
```

- 会话并发：同一用户同时只允许 1 个未结束会话（`CREATED/PREPARING/READY/IN_PROGRESS/PAUSED`）；结束后可创建新会话。
- 单题只能提交一次；重复提交返回 409，携带已有 `answerId`。
- 超时未作答可跳过，跳过题计 0 分并标记 `SKIPPED`，不影响继续作答；报告等权平均时按 0 分计入。
- 追问（V1.1）：每场最多 2 次，追加题目 `seq = 当前最大 + 1`，同时 `question_count += 1`，不额外扣额度。
- 会话暂停保留上下文 24 小时，超时归档。
- 用户可在作答前主动放弃会话（`POST /interviews/{id}/abandon`）；未提交任何回答时返还额度，已作答不返还。

### 6.5 作答与流式评分

- 文本回答 10–4000 字符；少于 10 字提示“回答过短，可能影响评分”。
- 语音回答时长 10–300 秒，格式 webm/wav/mp3，≤ 25MB；ASR 失败可切换手动输入，不重复扣额度。
- 提交后 1 秒内必须出现首个反馈 Token；若 3 秒无响应，展示“正在重新连接”，客户端自动重试 1 次。
- 评分维度（每项 0–10，保留 1 位小数）：

| 维度 | 权重 | 评分关注点 |
|---|---|---|
| 内容相关性 `content` | 0.25 | 是否正面回答、是否覆盖问题要点 |
| 结构化表达 `structure` | 0.20 | 分层、逻辑连接、结论先行 |
| 专业深度 `depth` | 0.25 | 原理、取舍、数据、边界条件 |
| 岗位匹配 `fit` | 0.15 | 是否结合 JD 场景与技能要求 |
| 语言表达 `language` | 0.15 | 冗余、口头禅、术语准确性 |

> 题目主题（专业深度/项目经历/行为面试/岗位匹配）决定“问什么”；五维评分决定“怎么评”，两者是独立枚举，不要混用。

- 单题总分 = Σ(维度分 × 权重)，取值 0–10；报告总分 = 各题得分的等权平均 × 10，取值 0–100。
- 反馈必须包含：`strengths[]`、`improvements[]`、`evidence[]`（引用回答原文 ≤ 3 条）、`rewrittenAnswer`（建议改写，≤ 300 字）。FREE 套餐不生成 `rewrittenAnswer`，该字段返回 `null`。
- 评分结果落库后可重复查看，不重复计费。
- 内容安全：涉及违法、歧视、露骨内容时拒绝评分，返回 `CONTENT_REJECTED`，不计分、不扣额度。

### 6.6 面试报告

- 触发：用户点击“结束面试”或完成最后一题后自动触发。
- 生成方式：RabbitMQ 异步；P95 < 30s，超时 90s 标记失败并提供重试。
- 报告内容：
  1. 总分与五维雷达图；
  2. 一句话总评（≤ 80 字）与三条亮点、三条风险；
  3. 逐题拆解（题目、回答摘要、得分、证据、建议）；
  4. 改进计划（按优先级排序，含可执行动作与推荐练习方向）；
  5. 与目标 JD 的匹配度变化（面试前 vs 面试后评估）。
- 报告生成失败自动重试 3 次（5s/30s/2min），仍失败则站内通知并可手动重试；手动重试不扣额度，最多 3 次/报告。
- PDF 导出（V1.1）为异步任务，生成后提供 7 天有效预签名链接。

### 6.7 额度与订阅

| 套餐 | 价格 | 额度 | 限制 |
|---|---|---|---|
| FREE | ¥0 | 每月 3 次面试 + 3 次简历解析 | 单题反馈不含“建议改写” |
| PRO | ¥39/月 | 每月 30 次面试 + 不限解析 | 优先生成队列、PDF 导出 |
| 次数包 | ¥9.9/3 次 | 永久有效 | 不区分套餐 |

**扣减规则**：

1. 创建会话时预扣 1 次面试额度；出题失败全额返还。
2. 上传简历时预扣 1 次解析额度；解析失败自动返还。
3. 单题评分不单独扣额度。
4. 报告重试、PDF 重试不扣额度。
5. 用户在未提交任何回答前主动放弃会话，全额返还面试额度；已作答不返还。
6. 退款/补偿只能由 ADMIN/SUPPORT 操作，必须写审计日志。

**防刷规则**（与 [key-challenges.md](./key-challenges.md) 难点五一致）：

- 免费用户每日最多创建 3 个会话，无论额度是否充足。
- 同一设备指纹 24 小时内最多绑定 3 个新账号。
- 同一 IP 每分钟注册 ≤ 3、登录 ≤ 10。
- 回答内容相似度 ≥ 0.95 的重复提交只计一次有效评分，仍提示用户。
- 全局成本熔断：单用户日成本超 ¥3 或全站小时成本超预算时，降级到小模型并告警。

### 6.8 管理端

- 题库：单条/批量导入（JSONL/CSV）、上下架、标签、难度、参考答案、向量化状态、检索命中统计。
- Prompt：模板列表、版本 diff、变量校验、发布/归档、灰度比例、实验指标对比、一键回滚。
- 用户：查询、禁用、额度调整、会话与调用记录。
- 调用日志：按场景/模型/状态/耗时/用户筛选，可查看脱敏后的 Prompt 与输出（仅 ADMIN，操作留痕）。
- 评测：触发 RAG 召回评测与评分一致性评测，展示基线对比。
- 看板：DAU、会话完成率、TTFT P95、Token 成本、错误率、额度拒绝率。

## 8. 数据与隐私

- 简历、JD、回答均属用户内容：传输 TLS 1.3，存储 AES-256（MinIO SSE + PG 列级加密用于手机号/邮箱）。
- 发送给 LLM 前做 PII 最小化：手机号、邮箱、身份证号默认脱敏；用户可在设置中关闭“允许使用简历原文”。
- 不将用户内容用于模型训练；与供应商签订零留存协议（如启用）。
- 用户可导出全部数据（JSON）与删除账号；删除后 7 天内完成内容清理与账号匿名化。
- 日志中不记录完整简历与回答正文，仅记录哈希、长度、Token 数；调试采样需用户授权且 24h 自动清理。
- 数据保留：原文件 180 天；会话与报告 24 个月；调用日志 90 天；审计日志 3 年。

## 10. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| LLM 输出不稳定/JSON 不合法 | 评分失败 | 结构化 Schema + 修复重试 + 降级模板 |
| 供应商限流或故障 | 不可用 | 多供应商路由、超时熔断、小模型降级、排队提示 |
| RAG 召回差导致题目泛化 | 用户流失 | 混合检索 + 重排 + 离线评测门禁 + 人工抽检 |
| Prompt 注入（简历/JD 中藏指令） | 越权/跑题 | 不可信内容定界、无工具权限、输出校验、内容审核 |
| 刷额度/薅羊毛 | 成本失控 | 额度 + 限流 + 设备指纹 + 成本熔断 |
| 简历隐私泄露 | 合规事故 | 加密、脱敏、最小权限、审计、可删除 |
| 评分被认为“不公” | 投诉 | 展示评分依据与原文证据、允许申诉、人工复核入口 |

## 11. 版本规划

- **MVP（v1.0）**：账号、简历解析、JD、8 题文字面试、流式评分、报告、题库/Prompt/日志管理、额度（免费）。
- **V1.1**：语音作答与 ASR、追问、套餐与模拟支付、PDF 导出、RAG 评测看板。
